# 参考优先级与冲突处理

## 1. 四个控制参考的职责

1. **《规则数26-V3(1).docx》：范围/实体粒度权威**
   - 决定8大类、业务范围和实体粒度。

2. **《知识规则模版.md》：JSON表达与逐子类语义最高权威**
   - 决定每一子类的sets、parameters、description及四字段JSON。

3. **《调度专项符号统一说明-V1.docx》：符号/公式权威**
   - 决定T/U/S/Q/O/N、IU/OU/IT/OT/UQ/OUSQ/CDUsk等数学语义。

4. **《规则数26-V3_规则数量整理.xlsx》：覆盖数量基线**
   - 决定大类目标和子类/子类组数量提示；
   - 用于表格首轮后的剩余量核对；
   - 不用于凑数。

以上四个文件均为 R0 控制参考，不是现场事实源。

## 2. 现场事实源的提取优先级

**提取顺序：P1 → P2 → P3 → P4 → P5。**

- P1：原生结构化数据表（XLSX/XLS/CSV/TSV）
- P2：DOCX/PDF/MD中的结构化表格
- P3：正式规程、操作说明、规则文本
- P4：流程/拓扑/工艺链说明
- P5：叙述性说明、会议纪要、辅助材料

P1首先建立规则底座；表格首轮后必须先计算规则缺口，P2–P5只补缺。

## 3. 提取优先级与冲突权威性不是一回事

冲突时按以下因素综合：
1. 明确生效日期/修订版本的正式批准文件；
2. 当前版本现场主数据/参数表；
3. 其他结构化数据；
4. 正式技术说明；
5. 叙述性材料。

不能仅因为表格先读，就忽略明确更新后的正式规程。

## 4. 重复与冲突

- 同一dedup_key + 同值：duplicate evidence，最终只输出1条；
- 同一dedup_key + 不同值：conflict/revision candidate，不得输出2条近义规则；
- 有明确新版：保留新版，旧来源记secondary/superseded；
- 无法判断新版：标记conflict，暂不输出确定规则。

## 5. 数量控制

- exact target达成：关闭新增，后续文档只复核；
- approx/interval：仅作覆盖指导；
- unspecified：不造假剩余数量；
- 大类内部数量不一致：报告差异，不凑数；
- 超目标：先查重复、实体粒度、分类映射错误。

## 6. 禁止

- 禁止混合所有文件直接抽取；
- 禁止低优先级文本重复生成表格已覆盖规则；
- 禁止使用数量目标制造不存在的规则；
- 禁止往最终JSON增加审计字段；
- 禁止凭物料名猜拓扑。
