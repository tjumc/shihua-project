# 多文件梳理与表格优先补缺流程

## 一、为什么必须先梳理

多文件直接混抽容易出现四类错误：
1. 同一事实从 XLSX、DOCX、PDF 重复生成多条规则；
2. 低质量叙述覆盖高质量结构化数据；
3. 已经满足数量/实体覆盖的子类仍继续搜索，导致规则膨胀；
4. 不同文件使用不同实体名称，造成同一实体被重复当作多个对象。

因此本 Skill 必须先完成文件梳理，再开始规则生成。

## 二、Preflight 文件梳理

递归扫描输入根目录，保留完整相对路径。每个文件至少记录：
- source_id
- relative_path
- file_type
- priority
- evidence_role
- 是否包含结构化表格
- 可能涉及的大类
- 可能涉及的子类
- 预计可贡献的规则内容
- read_order
- status

必须先生成 `文件梳理与提取计划.md` 与 `source_inventory.json`。

## 三、提取优先级

### P1 原生结构化数据表
`.xlsx/.xls/.csv/.tsv`。

优先提取：
- 数值上下限
- 额定/最大/最小负荷
- 收率
- 物性
- 配方
- 库存
- 需求/产量（注意语义区分）
- 拓扑映射表

### P2 文档中的结构化表格
DOCX/PDF/MD 中的明确表格。只有 P1 首轮后的缺口允许时才新增规则。

### P3 正式规程/规则文本
适合停工、切换、时窗、检修、操作频次、经验阈值。

### P4 流程/拓扑说明
适合 IU/OU/IT/OT 与流程协同。必须有明确连接关系。

### P5 叙述性材料
仅在其他来源缺失且文本明确时补充。

### R0 控制参考
`知识规则模版.md`、`调度专项符号统一说明-V1.docx`、`规则数26-V3(1).docx`、`规则数26-V3_规则数量整理.xlsx` 等不作为现场事实源。

## 四、表格首轮

1. 只处理 P1；
2. 在 P1 内仍按 8 大类顺序；
3. 每条候选规则生成 `dedup_key`；
4. 同一 dedup_key、数值一致：只保留一条，其他来源记为 secondary evidence；
5. 同一 dedup_key、数值不同：进入 conflict，不重复输出；
6. 每条已输出规则必须绑定 `target_group_id`。

## 五、数量缺口核对

表格首轮结束后，读取 `config/rule_count_baseline_v3.json`：

- exact：`remaining=max(target-extracted_unique,0)`；达到目标后关闭新增；
- approx / interval：数量仅指导覆盖，不作为硬凑数指标；
- unspecified：不计算伪剩余数，只检查模板子类与实体槽位是否有空缺；
- category target：作为大类总量控制线。若子类数量之和与大类目标不一致，以“报告冲突 + 不凑数”为原则。

生成 `rule_gap_after_tables.json` 和 `剩余规则补缺计划.md`。

## 六、只补缺，不重复

文档补缺阶段只允许：
1. target_group 尚有 remaining；或
2. 某模板子类完全未覆盖；或
3. 已知实体 coverage slot 未覆盖；或
4. 表格明确缺失某种语义（如停工时窗、检修事件、经验阈值）。

已经完成的 target_group：
- DOCX/MD/PDF 可阅读用于复核；
- 不得再产生新规则；
- 如果发现更新值，转入 conflict/revision 流程。

## 七、实体槽位优先于纯数量

有明确实体清单时，必须维护 coverage slots：
- 10个原油罐
- 30种原油
- V3装置类别
- 10类逻辑实体罐
- 50种产品（若现场名册可得）

例如目标10条且表格已有10条，但其实是同一个实体重复10次，应判覆盖失败，不能仅看数量。

## 八、去重身份

`dedup_key` 不放入最终JSON，仅放 manifest。推荐：

`big_category + subcategory + normalized sets signature + sorted parameter semantic keys`

其中 sets signature 由每个 set 的 `set_name/subset_name/element` 规范化后排序得到。

同 identity 不同值 = conflict；同 identity 同值 = duplicate evidence。

## 九、最终原则

规则数量表是覆盖控制工具，不是造数工具。
- 不足：有证据才补；
- 达标：停止生成，只复核；
- 超出：先查重复、实体粒度、分类错误；
- 约数/歧义：报告，不强行对齐。
