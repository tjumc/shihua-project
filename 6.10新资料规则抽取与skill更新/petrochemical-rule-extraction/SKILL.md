# 石化项目知识规则提取 Skill

## 1. 使用场景

当用户要求从石化项目资料中自动提取知识规则时，使用本 Skill。根据《课题4规则规模评估-知识规则示例.docx》，本 Skill 一次性覆盖 5 类抽取对象：

1. 质量标准规则
2. 工艺规范规则
3. 流程特征规则
4. 操作规程规则
5. 调度经验规则

典型输入是一个项目目录，目录内可能包含：

- PDF：质量标准、操作规程、工艺卡片、调度制度、应急预案、工艺规范、设备规程等；包括文本型 PDF 和扫描/图片型 PDF；
- DOC/DOCX：管理规定、会议纪要、经验总结、调度要求、质量制度、操作法等；
- TXT/MD：OCR 文本、人工整理文本；
- XLS/XLSX：已有规则表、工艺参数表、质量指标表、台账、调度记录表、罐区记录表。

目标是从多源文件中抽取可用于调度算法、规则库、检索问答和后续核验流程的数据化知识规则，最终只输出 `extracted_rules.xls` 和 5 类规则 JSON，并保留来源文件、页码/表名/行列、原文证据。

解析扫描 PDF 时，默认使用 `claude` conda 环境中的 OCR 依赖：

```bash
conda activate claude
```

也可在脚本命令中使用 `conda run -n claude ...`。中文扫描件优先使用 Tesseract `chi_sim+eng` 语言包。

当用户要求“扫描整本书”“存成 docx”或“英文资料解析成中文”时，必须先使用内置 `scripts/pdf_to_chinese_docx.py` 将每个 PDF 整本转换为按页定位的中文 DOCX，再基于 DOCX/解析文本抽取规则。英文 PDF 默认翻译为中文；扫描 PDF 默认 OCR 后写入 DOCX。

本 Skill **只负责规则提取**，不生成 mask 字段，不做人工核验判断，不输出置信度字段。

## 2. 内置表格模板

本 Skill 已内置空白 Excel 模板：

```text
templates/rule_summary_template.xls
```

模板包含 5 个子表：

1. `1、质量标准规则`
2. `2、工艺规范规则`
3. `3、流程特征规则`
4. `4、操作规程规则`
5. `5、调度经验规则`

模板保留列头和 5 个子表。执行抽取时，应优先复制该模板作为最终结果文件：

```text
output/extracted_rules.xls
```

然后分别写入 5 个子表。不要修改用户原始文档，不要覆盖模板文件本身。

## 3. 核心目标

抽取的规则不是简单摘抄原文，而是把文档中的质量指标、操作要求、约束边界、上下限、物料流向、联动关系、异常处置、切换逻辑等整理成“专业化、普遍化、可计算、可追溯”的知识规则。`规则内容` / JSON `rule_content` 必须直接写结论式规则，不使用“针对+原文片段”的拼接表达，不把页码、文件名、表号、目录文字、省略号、OCR 乱码或长证据片段写入规则正文。

必须重点关注以下信息：

1. **物料/产品质量**：原油、中间物料、航煤、汽油、柴油、气体及化工产品、化工辅料、乙烯、丙烯、聚乙烯、聚酯切片、涤纶长丝、涤纶短纤等。
2. **装置/系统**：常压、常减压、催化、加氢、重整、焦化、乙烯裂解、聚乙烯、聚丙烯、聚酯、纺丝、公用工程、罐区、码头、储运、冷换系统、加热炉、反应系统、分馏系统等。
3. **流程/协同关系**：关键物料标准流向、上游/下游装置衔接、罐区缓冲、调合、芳烃链、烯烃链、聚酯链、前纺后纺协同等。
4. **参数/指标**：温度、压力、流量、负荷率、液位、界位、回流比、氢油比、剂油比、主风量、真空度、COT、WABT、纯度、收率、硫含量、密度、馏程、闪点、凝点、冰点、辛烷值、十六烷值、熔融指数、粘度、库存上下限、处理量、升降温速率、提降量速率等。
5. **操作动作**：提量、降量、切油种、切牌号、开停工、热循环、改循环、切出、投用、置换、吹扫、预热、升温、降温、补充、排放、启泵、停泵、阀位调整、报批、告知、确认等。
6. **约束表达**：必须、严禁、不得、应、宜、控制在、保持、低于、高于、不超过、不小于、达到、优先、先……再……、若……则……、当……时……。
7. **调度价值**：规则应能为调度算法提供硬约束、软约束、质量边界、流程拓扑、阈值约束、状态切换约束、操作步骤、异常处置策略、联动调整逻辑或优化优先级。

## 4. 规则类型体系

### 4.1 质量标准类

1. 变负荷约束规则

3. 常压装置负荷与运行模式规则
4. 催化装置负荷与运行模式规则
5. 加氢装置负荷与运行模式规则

8. 纺丝前纺与后纺协同规则
9. 中间罐区缓冲与调合协同规则
10. 其他流程特征规则

### 4.4 操作规程类

聚焦具体装置、罐区或系统的开停工、切换、投退用、异常处置、巡检确认、安全确认等可执行操作步骤和顺序约束。优先识别以下子类型：

## 5. 输出字段规范

5 个子表均使用相同的 11 个字段，字段顺序必须保持如下，不得增加 mask、置信度、人工核验、人工核对字段。

| 顺序 | 字段 | 说明 |
|---:|---|---|
| 1 | 规则编号 | 自动生成。各类规则使用对应编号前缀，例如 `QS-RAW-001`、`R1-001`、`FLOW-MAT-001`、`SOP-TNK-001`、`EXP-SMO-001`。 |
| 2 | 规则名称 | 15-30 字，体现物料/装置、场景、约束对象或经验策略。 |
| 3 | 知识类型 | 固定为“质量标准类”“工艺规范类”“流程特征类”“操作规程类”或“调度经验类”。 |
| 4 | 子类型 | 从本 Skill 的规则类型体系中选择。 |
| 5 | 适用范围 | 物料/产品/装置/系统 + 场景，例如“常压蒸馏装置停工降负荷场景”。 |
| 6 | 规则内容 | 专业化、普遍化后的规则表达。 |
| 7 | 来源文件 | 文件名，不写绝对路径；多来源用分号分隔。 |
| 8 | 具体页码 | PDF/DOC 页码；Excel 用 `Sheet=xxx; Row=xx`；文本用行号/段落号。 |
| 9 | 原文内容 | 支撑该规则的最小充分原文片段。 |
| 10 | JSON | 与 `工艺规范规则.json` 示例一致的单条规则 JSON 字符串。 |
| 11 | 备注 | 泛化说明、适用限制、是否由多句归纳、是否存在参数冲突等。 |

## 6. 抽取原则

### 6.1 可以抽取为规则的内容

满足以下任一条件，可以抽取：

1. 含有明确质量指标或合格边界：如硫含量、密度、馏程、闪点、冰点、纯度、熔融指数、粘度等。
2. 含有明确数值边界：如 `≤5℃/h`、`80%-105%`、`液位控制在 40%-60%`。
3. 含有物料流向、上下游路径或跨装置协同：如“常压渣油送催化裂化装置”“负荷变化需提前通知下游”。
4. 含有状态切换条件：如“当……时，应……”“若……则……”。
5. 含有操作顺序或规程步骤：如“先降量，再平衡液位，最后恢复”。
6. 含有安全红线：如“严禁”“不得”“必须确认”。
7. 含有异常处置：如停电、雷暴雨、泄漏、着火、设备跳停、质量超差、库存高低限。
8. 能转换为调度算法输入：硬约束、软约束、质量边界、流程拓扑、阈值、优先级、动作序列、条件触发器。

### 6.2 不要抽取的内容

以下内容不要作为独立规则，除非与具体指标、约束、流向或操作动作绑定：

1. 纯背景介绍、岗位职责、组织架构。
2. 没有操作含义或质量边界的定义性文本。
3. 单纯设备清单、物料清单。
4. 无法定位来源或无证据支持的常识性推断。
5. 只有“加强管理”“密切关注”等空泛表述。

### 6.3 泛化原则

- 保留关键参数、阈值、单位、物料、装置、流向、操作动作。
- 将过细步骤合并为调度可用规则，但操作规程类必须保留关键步骤顺序。
- 不改变原文的数值、上下限、方向和安全含义。
- 不凭空增加原文没有的阈值、来源去向或操作条件。
- 若规则由多个原文句子归纳得到，在备注中说明“由多句归纳”。
- 若规则跨多个文件合并，来源文件和页码必须列出多个证据。

## 7. 工作流程

### Step 1：建立文件清单

在项目目录中递归扫描文件，忽略临时文件、缓存文件、模型文件、图片缓存、日志压缩包等。建议保留：

```bash
find <PROJECT_DIR> -type f \
  \( -iname "*.pdf" -o -iname "*.doc" -o -iname "*.docx" -o -iname "*.txt" -o -iname "*.md" -o -iname "*.xls" -o -iname "*.xlsx" \) \
  ! -iname "~$*" \
  ! -path "*/.git/*" \
  > source_files.txt
```

可临时使用内置脚本辅助生成 manifest，但最终交付物不要包含 `source_manifest.json`：

```bash
python scripts/build_source_manifest.py <PROJECT_DIR> <OUTPUT_DIR>/_source_manifest.json
```

### Step 2：复制空白模板

从 Skill 目录复制模板：

```bash
mkdir -p <OUTPUT_DIR>
cp templates/rule_summary_template.xls <OUTPUT_DIR>/extracted_rules.xls
```

后续所有规则写入 `<OUTPUT_DIR>/extracted_rules.xls` 的 5 个子表。

### Step 3：解析文本与定位信息

按文件类型解析：

- PDF：先按页抽取嵌入文本，保留 `page_no`；若页面文本过少、乱码或整页为图片，则按扫描 PDF 走 OCR。
- DOC/DOCX：尽量转换为按页或按段落编号；无法稳定页码时，使用“段落号/标题路径”。
- TXT/MD：按行号或段落号定位。
- XLS/XLSX：按 sheet、row、column 定位；表头和单位必须一并读取。

扫描/图片型 PDF 的 OCR 流程：

1. 优先在 `claude` conda 环境执行 OCR 依赖，确保 `tesseract --list-langs` 包含 `chi_sim` 和 `eng`。
2. 对每个 PDF 先尝试文本抽取；单页有效文本少于约 30 个字符、明显乱码或无法抽取时，判定为需 OCR 页面。
3. 使用内置脚本逐页生成带页码的 OCR 文本块：

```bash
conda run -n claude python /Users/xiluo/.codex/skills/petrochemical-rule-extraction/scripts/ocr_scanned_pdf.py \
  <INPUT_PDF> <OUTPUT_DIR>/_ocr_work/<PDF_STEM> --lang chi_sim+eng --dpi 300
```

4. OCR 结果中的 `source_file`、`locator`、`text` 作为后续候选规则抽取输入；`locator` 必须保留为 `page=页码`。
5. OCR 中间文件如 `_ocr_work/**/ocr_pages.jsonl`、`ocr_text.txt`、`ocr_manifest.json` 仅用于解析过程，不作为最终交付物。
6. 若中文语言包缺失、页面倾斜严重、表格线导致识别错误或关键阈值难以确认，必须在最终回复的主要风险中说明；不得凭 OCR 猜测补全阈值。

每个文本块建议结构：

```json

  "source_file": "xxx.pdf",
  "locator": "page=26",
  "section_title": "开工升温",
  "text": "为了维持系统稳定……温度升降速度≯5℃/h。"

```

### Step 3A：整本 PDF 转中文 DOCX

当输入包含书籍、扫描件或英文资料时，先生成可复用中文 DOCX：

```bash

  <PROJECT_DIR> <OUTPUT_DIR>/parsed_docx --batch --translate auto --ocr-lang chi_sim+eng --ocr-workers 2
```

脚本行为：

1. 文本型 PDF：按页抽取文本，保留 `文件名 | page=页码`。
2. 扫描/图片型 PDF：对低文本页执行 OCR，保留页码。
3. 英文页：默认翻译成中文；优先使用本地 Argos `en -> zh` 模型，失败时尝试 MyMemory，仍失败则以 `[未翻译]` 标记保留英文原文。
4. 中文页：直接写入 DOCX，不重复翻译。
5. 每个 PDF 生成一个 `.docx` 和一个同名 `.manifest.json`；批量目录生成 `_pdf_to_chinese_docx_summary.json`。
6. DOCX/manifest 是解析中间产物。若用户明确要求保留 DOCX，则放在输出目录的 `parsed_docx/`；若用户只要求最终规则表，则不把 DOCX 放入最终交付清单。

对大体量扫描书，允许使用 `--max-pages` 先抽查 OCR 质量；正式执行必须去掉 `--max-pages` 以处理整本书。

### Step 5：抽取候选规则

对每个候选片段判断：

1. 是否包含可执行动作、质量边界、流向关系或约束；
2. 是否包含物料/产品/装置/对象/条件/参数；
3. 是否能转化为规则内容；
4. 应归为质量标准类、工艺规范类、流程特征类、操作规程类还是调度经验类；
5. 是否需要与相邻片段合并。

### Step 6：规则标准化

根据类别统一表达：

- 质量标准类：`【物料/产品】的【质量指标】应满足【范围/阈值/标准】，适用于【场景/装置/产品牌号】。`
- 工艺规范类：`当/在【条件/场景】下，【装置/对象】应/不得【操作动作】，并将【参数】控制在【范围/阈值】，以避免/保证【目的】。`
- 流程特征类：`【物料/产品】由【来源】进入/送至【去向】，在【条件】下需满足【负荷/质量/时序/缓冲】协同要求。`
- 操作规程类：`在【操作场景】下，应按【关键步骤顺序】执行，并确认【安全/质量/设备/状态条件】。`
- 调度经验类：`当【调度场景/异常条件】出现时，应优先【调度策略/联动动作】，以保证【平稳性/安全边际/质量/效益】。`

不是每条规则都要强行包含所有要素，但应尽量具备：条件、对象、动作或关系、参数、约束方向、目的。

## 8. 去重与冲突处理

### 8.1 去重判断

以下字段高度相似时，应合并或去重：

- `规则内容` / `rule_content` 完全相同；
- 知识类型和子类型相同；
- 物料/产品/装置/系统相同；
- 操作场景、流向关系或质量指标相同；
- 参数对象相同；
- 阈值相同或等价；
- 原文证据相邻或重复。

合并时保留：

- 更明确的规则内容；
- 更多来源证据；
- 更完整参数单位；
- 更利于调度算法使用的泛化表达。

### 8.2 冲突处理

若不同文件中同一指标或参数阈值冲突：

1. 不要擅自二选一。
2. 输出多条规则或在备注中标记冲突。
3. JSON 的 `notes` 字段中标记冲突来源和差异。
4. 不生成单独的 `conflict_rules.csv`。

## 9. JSON 输出 Schema

5 个 JSON 文件均为 JSON 数组，数组内每条规则的字段格式必须参考项目中的 `工艺规范规则.json`。每条规则只使用以下 15 个顶层字段，字段顺序建议保持一致：

```json
{
  "rule_id": "R1-001",
  "rule_name": "常压停工降量速率规则",
  "knowledge_type": "工艺规范类",
  "sub_type": "变负荷约束规则",
  "applicable_scope": "常压蒸馏装置停工降负荷场景",
  "rule_content": "常压装置停工时按20 t/h开始降量，不宜一次性大幅降量。",
  "source_file": "延炼-300万吨常压蒸馏装置操作规程.pdf",
  "locator": "page=停工进度安排页",
  "evidence_text": "第一天0:00开始以20t/h降量。",
  "parameters": [
    {
      "name": "降量速率",
      "value": "20",
      "unit": "t/h",
      "operator": "按",
      "normalized_value": 20,
      "normalized_unit": "t/h"
    }
  ],
  "devices": ["常压装置"],
  "operations": ["停工", "降量"],
  "conditions": ["停工时"],
  "constraint_type": "操作速率约束",
  "notes": "显式速率要求"
}
```

顶层字段固定为：

```text
rule_id, rule_name, knowledge_type, sub_type, applicable_scope, rule_content, source_file, locator, evidence_text, parameters, devices, operations, conditions, constraint_type, notes
```

`parameters` 为数组，每个参数对象字段固定为：

```text
name, value, unit, operator, normalized_value, normalized_unit
```

对质量标准类，可将物料/产品写入 `devices` 或 `applicable_scope`，质量指标写入 `parameters`，规则类型写入 `constraint_type`。对流程特征类，可将来源、去向、协同对象写入 `devices`，流向/协同动作写入 `operations`，触发场景写入 `conditions`。对操作规程类，可将关键步骤顺序写入 `operations`，并在 `notes` 中说明“按原文顺序整理”。

JSON 中不得输出 `mask1`、`mask2`、`confidence`、`need_manual_review` 等字段。

## 13. 质量验收标准

完成后必须自检：

1. 每条规则必须有来源文件。
2. 每条规则必须有原文证据。
3. 含数值的规则必须保留单位。
4. 质量标准类必须保留指标名称、阈值/范围、适用物料或产品。
5. 流程特征类必须保留来源、去向、物料或协同对象。
6. 操作规程类必须保留关键步骤顺序或触发条件。
7. 规则内容不得改变原文阈值方向，例如 ≤ 不能改成 ≥。
8. `规则内容` / JSON `rule_content` 不得重复；发现重复时必须继续筛选候选规则或合并来源证据后再输出。
9. `规则内容` / JSON `rule_content` 必须是梳理后的结论式规则，不得包含“针对”、长原文片段、省略号、页码、文件名、表号、目录文字、OCR 乱码或机械解析词。
10. 5 个子表字段必须完全一致，且顺序为：规则编号、规则名称、知识类型、子类型、适用范围、规则内容、来源文件、具体页码、原文内容、JSON、备注。
11. 不得出现 mask、置信度、人工核验、人工核对字段。
12. 5 个 JSON 文件必须能被解析，且每条规则只包含 `工艺规范规则.json` 示例中的 15 个顶层字段。
13. `parameters` 内每个对象只包含 `name`、`value`、`unit`、`operator`、`normalized_value`、`normalized_unit`。
14. Excel 必须使用内置模板并保留列头和格式。
15. 冲突规则必须在 `备注` 和 JSON `notes` 中说明。
16. 扫描 PDF 的 OCR 文本必须保留页码定位；OCR 低可信或疑似错字的关键阈值不得直接作为确定规则，需在 `备注` 和 JSON `notes` 中说明。
17. 最终输出目录不要包含 CSV、JSONL、报告、manifest、OCR 中间目录或冲突清单文件。
