# 规则库自动核验方案

更新日期：2026-04-30

## 1. 目标

这套方案的目标不是自动替代人工口径判断，而是把规则库维护中重复、机械、易漏的核验动作脚本化，稳定输出一份可追溯的异常清单。

当前交付的最小可用版本包括：

- 自动读取正式主源与审计链路
- 自动核对数量、编号和关键字段是否闭环
- 自动扫描 JSON 残留、问号损坏等脏数据
- 自动识别重复命名和高风险重复来源页
- 自动生成 JSON 报告和 Markdown 报告

## 2. 当前已自动化的部分

以下检查已经由脚本自动完成：

1. 文件存在性检查
- `主总表.xlsx`
- `终版审计表.xlsx`
- `提取内容逐项审计.xlsx`
- `规则库_当前版.json`

2. 表结构检查
- 必需 sheet 是否存在
- 必需表头是否完整

3. 正式链路闭环检查
- `规则总表`
- `最终交付表`
- `终版审计明细`
- `逐项审计`
- `规则库_当前版.json`

4. 数量与编号检查
- 各链路规则数是否一致
- 规则编号是否缺失、断裂、外溢

5. 关键字段一致性检查
- 规则名称
- 所属大类
- 所属子项
- 来源文件
- 来源页码

6. 异常文本扫描
- `JSON：`
- `JSON:`
- `自然语言：`
- `自然语言:`
- 连续 `?` 问号损坏

7. 重复风险提示
- 同名规则
- 同名且同来源文件同页码规则
- 同内容跨类别规则

## 3. 仍需人工处理的部分

脚本只负责“发现”，不负责替你做最终口径判断。以下事项仍建议人工确认：

- `规则163/194` 这类可能影响规则总数的重复计数问题
- `规则092/161`、`规则131/151` 这类是否长期保留双口径的建模问题
- 是否存在“漏提规则”这一类需要回看 PDF 原文的判断

换句话说，这套自动化的定位是：

- 自动把低风险、重复劳动收掉
- 自动把高风险条目标红
- 让人工只处理真正需要判断的少数项

## 4. 脚本位置

- 校验脚本：`scripts/validate_rule_library.py`
- 现有导出脚本：`scripts/export_rules_to_json.py`
- 现有测试：
  - `tests/test_validate_rule_library.py`
  - `tests/test_export_rules_to_json.py`

## 5. 运行方式

在项目根目录执行：

```powershell
python scripts/validate_rule_library.py
```

默认会在以下目录生成报告：

- `提取结果/02_过程追溯/05_规则追溯核对/自动核验/`

生成 2 份产物：

- `YYYY-MM-DD_规则库自动核验报告.json`
- `YYYY-MM-DD_规则库自动核验报告.md`

脚本退出码规则：

- `0`：没有结构性错误
- `1`：存在结构性错误，需要先修主链路

## 6. 如何看报告

报告分为 3 层：

1. `errors`
- 结构性错误
- 例如：缺文件、缺 sheet、数量不一致、编号缺失、关键字段跨表不一致
- 这类问题必须先修

2. `warnings`
- 机器能明确识别的风险
- 例如：重复命名、JSON 残留、问号损坏

3. `manual_review`
- 需要人工复判的高风险项
- 例如：同名同页同源、同内容跨类别

## 7. 推荐使用流程

每次规则库整理后，建议固定执行下面 4 步：

1. 先更新 `主总表.xlsx`
2. 再执行 `python scripts/export_rules_to_json.py`
3. 再执行 `python scripts/validate_rule_library.py`
4. 最后只处理报告里的 `errors` 和 `manual_review`

## 8. 这套方案的意义

对当前项目来说，这套自动化方案最有价值的不是“替人判断”，而是：

- 保证正式链路始终闭环
- 第一时间发现脏数据回写
- 降低每轮全表人工复查成本
- 让后续 agent 直接接入同一套校验标准

如果后续继续扩展，可以在这套基础上再加：

- 自动生成待人工复判 Excel
- 自动比对历史版本快照差异
- 自动汇总成周报口径
