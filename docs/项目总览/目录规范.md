# 项目目录规范

更新日期：2026-06-03

## 顶层目录分工

| 目录 | 用途 |
| --- | --- |
| `docs/` | 项目文档中心，只放便于阅读和汇报的 Markdown 文档 |
| `提取结果/` | Excel、审计表、核验产物、交付快照和周报归档 |
| `json规则库/` | 当前 JSON 规则库、分类 JSON、历史版本和模板 |
| `延长数据/` | 项目方原始资料 |
| `石化通用规则源文件/` | 通用规则使用的标准源文件 |
| `scripts/` | 导出、校验和维护脚本 |
| `skill documents/` | 规则核验 Skill 原始包 |
| `5.27规则内容更新skill/` | 规则增量更新 Skill 和模拟实验 |

## docs 文档中心结构

`docs/` 下尽量只保留一层业务分类，不再继续深层嵌套：

| 目录 | 放什么 |
| --- | --- |
| `项目总览/` | 当前状态、目录规范、阅读顺序 |
| `周报汇报/` | 周报、汇报稿、预检查稿 |
| `规则与核验/` | 规则提取、通用规则、核验方案、核验总结 |
| `Skill说明/` | 规则核验 Skill、增量更新 Skill 的说明和验证报告 |
| `技术报告/` | 技术报告大纲、正文草稿、资料索引 |
| `参考资料/` | 参考资料说明 |
| `plans/` | 历史计划文档，保留但不作为日常入口 |

## 维护原则

- 新的汇报稿放入 `docs/周报汇报/`，完整归档仍放入 `提取结果/00_项目总览/周报归档/`。
- 新的规则说明、核验总结放入 `docs/规则与核验/`。
- Excel、PDF、截图等产物不放入 `docs/`，仍保留在结果区或源文件区。
- `docs/` 的目标是“让人读得懂”，不是替代原始成果目录。
- 日常新增文档尽量控制在两层以内。
- 现行标准放在 `石化通用规则源文件/` 根目录；废止标准放入 `石化通用规则源文件/废止不参考/`。
- 文件清理按 `docs/项目总览/文件保留与清理规则.md` 执行。
