## 2. 本周目标

建立一版小规模、可追溯的通用知识规则样例库。

建议规模：

- `GB/T 32151.15-2023`：先抽取 10-15 条。
- `GB 16994.2-2021`：先抽取 10-15 条。
- 合计形成 20-30 条通用规则样例。

目标不是一次抽全，而是验证通用规则抽取口径是否可行。

## 3. 规则分类

建议先分成 6 类：

| 大类 | 说明 | 主要来源 |
| --- | --- | --- |
| 碳排放核算边界规则 | 报告主体、设施、核算边界、排放源纳入范围 | GB/T 32151.15-2023 |
| 碳排放计量监测规则 | 计量器具、检测、数据采集、活动数据要求 | GB/T 32151.15-2023 |
| 碳排放核算方法规则 | 化石燃料燃烧、火炬、过程排放、购入电热等计算规则 | GB/T 32151.15-2023 |
| 数据质量与报告规则 | 数据质量控制、报告内容、报告格式、参数缺省值 | GB/T 32151.15-2023 |
| 石化库区作业安全规则 | 库区作业、装卸、储运、现场控制、人员车辆要求 | GB 16994.2-2021 |
| 石化库区风险控制规则 | 防火、防爆、防静电、安全标识、应急与特殊作业接口 | GB 16994.2-2021 |

## 4. 抽取字段

建议每条规则至少记录这些字段：

| 字段 | 说明 |
| --- | --- |
| 规则编号 | 临时编号，如 `GEN-CARBON-001`、`GEN-SAFETY-001` |
| 规则名称 | 用一句话概括规则 |
| 知识类型 | 通用知识规则 |
| 子类型 | 碳排放核算、库区安全、计量监测等 |
| 适用范围 | 石油化工企业、石化库区、港口作业等 |
| 触发条件 | 何时适用该规则 |
| 规则内容 | 可执行、可判断的规则句 |
| 参数范围 | 有数值/范围/阈值时填写 |
| 来源标准 | 标准号和名称 |
| 来源条款 | 条款号、页码或章节 |
| 原文依据 | 摘录短句或概括依据 |
| 证据等级 | A：现行强制性国家标准；B：现行推荐性国家标准 |
| 是否需人工确认 | 是/否 |
| 备注 | 解析问题、适用边界、待补证据 |

## 5. 执行顺序

### 第一步：先抽碳排放规则

原因：

- `GB/T 32151.15-2023` 的 PDF 文本可直接抽取。
- 目录结构清晰，包含范围、术语、核算边界、计量监检测、核算方法、数据质量、报告格式。
- 适合快速形成第一版通用规则样例。

建议优先章节：

1. `1 范围`
2. `4 核算边界`
3. `5 计量与监检测要求`
4. `6 核算步骤与核算方法`
5. `7 数据质量管理`
6. `8 报告内容和格式`

### 第二步：再抽库区安全规则

原因：

- `GB 16994.2-2021` 是强制性国家标准，规则权重高。
- 但当前 PDF 文本抽取乱码，需要先解决 OCR 或解析问题。

建议先做人工/半自动试抽：

1. 识别目录和章节。
2. 选取最容易形成规则的 2-3 个章节。
3. 抽取 10-15 条规则样例。
4. 记录 OCR 或解析质量问题。

### 第三步：统一成样例表

建议输出文件：

```text
/Users/machong/shihua-project/石化通用规则源文件/通用知识规则样例_2026-06-02.xlsx
```

或先输出 Markdown 草稿：

```text
/Users/machong/shihua-project/石化通用规则源文件/通用知识规则样例_2026-06-02.md
```

### 第四步：接入现有 JSON 模板

样例表稳定后，再映射到当前项目 JSON 模板：

- `rule_id`
- `description`
- `sets`
- `parameters`

但本周优先保证“来源可追溯”和“规则口径稳定”，暂不急于批量 JSON 化。

## 6. 本周汇报口径

本周从专用规则抽取转向通用知识规则构建。由于专用规则仍需甲方验证，本周优先选择现行国家标准作为可信来源，暂不采用已废止标准。当前已确定两类通用规则来源：一类是石油化工企业碳排放核算与报告规则，另一类是港口石油化工库区作业安全规则。下一步将先从可直接解析的 `GB/T 32151.15-2023` 抽取首批碳排放通用规则，再处理 `GB 16994.2-2021` 的 OCR/解析问题并抽取库区安全规则，最终形成 20-30 条可追溯的通用知识规则样例。
