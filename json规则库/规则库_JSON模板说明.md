## 2. 为什么选这个模板

当前项目里实际有两种 JSON 参考口径：

- `规则总表` 口径：偏中间整理过程，字段更贴近抽取阶段
- `最终交付表` 口径：偏最终规则库表达，字段更稳定，也更适合后续机器消费

本次正式模板选择 `最终交付表` 口径，原因是：

- 它已经完成了知识类型、子类型、适用范围等归一化
- 它更接近最终交付结果，而不是中间整理状态
- 后续把 215 条规则批量整理成 JSON 时，口径更稳定

## 3. 模板结构

顶层结构：

- `meta`：模板元信息
- `rules`：规则对象数组

每条规则最小结构：

- `rule_id`
- `description`
- `sets`
- `parameters`

## 4. 字段映射

推荐按 `最终交付表` 做映射：

- `rule_id` <- `规则编号`
- `description` <- `规则内容`
- `sets[0].set_name = KnowledgeType`，`element <- 知识类型`
- `sets[1].set_name = SubType`，`element <- 子类型`
- `sets[2].set_name = Scope`，`element <- 适用范围`
- `parameters.触发条件.value <- 触发条件`
- `parameters.规则内容.value <- 规则内容`
- `parameters.参数范围.value <- 参数范围`
- `parameters.来源页码.value <- 来源页码`

## 5. 现阶段不放进 JSON 规则体的字段

下面这些字段目前仍建议保留在表格侧或后续扩展，不放进 v1 模板的规则体最小结构：

- `所属大类`
- `所属子项`
- `来源文件`
- `来源依据`
- `是否需人工确认`
- `备注`

这样做的原因是：当前样例表展示的 JSON 规则体本身就是“核心规则表达”，不是把整行表格原样序列化。

## 6. 与历史草稿 `规则库.json` 的关系

当前放在 [历史草稿与参考样例/规则库.json](</C:/Users/643/Desktop/石油项目/json规则库/历史草稿与参考样例/规则库.json>) 的旧草稿可以继续保留，但它当前存在这些问题：

- 不是合法的单一 JSON 文档
- 前面混有说明文字
- 多个示例对象之间缺少统一容器
- 有语法错误，例如对象之间缺少逗号

因此后续批量整理规则时，不建议继续直接在旧草稿上追加内容，而应以新的正式模板为准。

## 7. 下一步建议

如果开始整理 215 条规则，建议执行顺序如下：

1. 以 `01_当前结果/主总表.xlsx` 或 `最终交付表` 为唯一来源
2. 先确定是导出全部 215 条，还是先导出某一类规则
3. 按本模板批量生成 `rules` 数组
4. 再根据需要补充 `source` 或 `traceability` 扩展字段
